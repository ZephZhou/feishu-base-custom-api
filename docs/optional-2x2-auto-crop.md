# 可选「自动裁切4主图（2×2）」

> 操作界面已升级为模板生成策略；本文的裁切/持久化原理仍适用，当前默认值与操作以 [模板策略说明](template-generation-modes.md) 为准。

本功能只在现有图片模式上增加浏览器本地裁切，不改变 Render API、PROXY_TOKEN、CORS、请求追踪或超时，不添加外部裁图服务，不额外调用 OpenAI。

## 操作步骤

1. 像以前一样选择当前商品「白底图」、已保存的品牌参考图、Prompt 和输出附件字段。
2. 勾选 **「生成后自动裁切为4张主图（2×2）」**。默认不勾选，状态会保存在当前浏览器配置中；勾选后数量自动锁定 `n=1`，取消后恢复可选数量。若期间切换了模板，则以该模板的生成数量作为取消后的数量。取消勾选不会自动改回原尺寸，请按现有尺寸/结果容量限制调整数量；每批开始后固定本批裁切状态，中途改动只影响下一批。
3. 将宽、高设为相同值，推荐 **2880×2880**（符合现有自定义尺寸限制）。不会自动改变用户已填的宽高；长方形配置会显示中文错误并在付费请求前拦截。
4. 保持现有 Prompt 的商品要求，并在其中明确说明需要 **等分、无边框、无间隔的 2×2 拼版**。插件不自动改写 Prompt。例如可自行补充：

   > 输出一张正方形的2×2电商主图拼版，左上、右上、左下、右下分别是独立且完整的商品场景。四格尺寸相同，严格沿画布中心线等分，无边框、无留白间隔；每格商品不要跨越中线，保留商品Logo、文字和颜色。

5. 先单行、并发 1 运行。仍按原顺序读取商品图及品牌图，每行只提交一次生成请求。收到一张拼版图后，在浏览器内将四个象限分别四边内缩24个原始像素后，各导出为独立 PNG，按以下顺序一次调用 `batchUploadFile`，再追加到已选附件字段：

| 文件名前缀 | 区域（原图裁切起点） | 2880×2880 原图的输出 |
| --- | --- | --- |
| 主图01 | 左上（24,24） | 1392×1392 |
| 主图02 | 右上（1464,24） | 1392×1392 |
| 主图03 | 左下（24,1464） | 1392×1392 |
| 主图04 | 右下（1464,1464） | 1392×1392 |

日志成功时显示：**「已生成1张拼版图，成功裁切4张并回写飞书」**。默认跳过已有附件的行；如需追加，使用现有「继续生成（保留旧附件并追加）」选项。

## 实际尺寸与画面内容

裁切尺寸以 API **实际返回图片**为准：先按2×2等分，再对每个象限上、下、左、右各去掉24个原始像素。2880×2880 的象限1440×1440变为四张1392×1392；1600×1600变为四张752×752。输出边长为「实际原图边长 ÷ 2 − 48」，不会缩放回原来的象限尺寸。实际返回非正方形、奇数边长、或内缩后没有有效像素时会明确报错并保留原图下载，不会静默减小内缩量。

使用 `createImageBitmap()`、`drawImage()` 和 `canvas.toBlob()`，每块源区域与目标区域的宽高完全相同，不插值缩放、不加滤镜、不调用模型重新绘制。只取原图对应像素区域，PNG 无损导出；浏览器编码会重新生成文件元数据。测试逐像素比较了内缩后对应原图区域中的文字、Logo图案、颜色和透明区域。

裁切不会检查或重新安排画面内容，也无法保证模型一定按四格构图：如果商品跨过中心线，会按坐标切断。因此请检查原始拼版图，必要时调整下一次生成的 Prompt，而不是期望裁切自动修图。

## 24px安全内缩与黑边检查

四个象限各自处理，包括靠近中间十字分隔线的边；不是只裁整个拼版的外圈。例如左上象限取原图 `(24,24,1392,1392)`，右上从 `(1464,24)` 开始。源区域与输出区域大小相同，不做AI修图、模糊、背景填充或颜色处理。每个象限最外侧24px会被舍弃；超过24px的原始边线可能仍有残留。

内缩从4px提高为固定常量 `AUTO_CROP_INSET_PX = 24`，没有新增UI设置。对照检查覆盖原算法（内缩0）、旧默认4px与新默认24px：

- 不透明纯白模拟图在裁切和PNG导出后没有新增黑像素。
- 透明和半透明边缘的RGBA与原图对应区域逐像素一致，没有被Canvas转换成不透明黑色，复用Canvas也没有残留上一张内容。没有使用不透明背景去掩盖透明像素。
- 模拟原图每个象限自带的16px边框（含外边与中间分界线）在0px与4px裁切时仍有残留，新24px内缩可以从四张结果中全部去掉。

该案例已确认下载后的裁切PNG也能看到黑边，因此不只是飞书附件预览的问题；目视黑边仍需区分不透明黑色与透明像素在查看器背景上的表现。这些测试未复现Canvas或PNG导出自行制造黑边。由于没有本次线上出问题的原始拼版与裁切PNG文件，不能据此断言具体照片的黑边一定来自模型；可用保留的原图下载对照，区分原始边线、原图透明像素和飞书预览背景。本修复只去掉指定像素区域，不改变剩余图像内容。

## 失败与原图恢复

- Canvas / `createImageBitmap` 不可用时，在提交生图前给出中文提示。若浏览器能力在请求后失效、返回图不是正方形/小到无法内缩、导出失败或附件上传失败，均不会自动重新调用付费 API。
- **先保留拼版原图，再尝试裁切**。收到有效原始图片后，设置区会出现「下载拼版原图（行…）」链接；成功、裁切失败或上传失败后都可下载原图，方便自行裁图和上传，避免重新付费。
- 原图以 Blob 和下载链接保留在**当前页面内存**，不写入 localStorage / 品牌图数据库，也不自动上传额外的原图附件。请在刷新、关闭插件或退出浏览器前下载；页面退出后这些链接无法恢复。
- 下载保存后可点击「清除下载链接（释放内存）」。该操作只清理本页保留的原图，不影响飞书附件、品牌图、模板或设置。批量生成会保留多张原图，建议及时下载并释放内存。
- 四张裁切图全部准备好、四个上传 token 全部返回后，才读取当前附件并一次追加。上传失败不会清空原附件；写回失败可能留下已上传但未引用的文件，不会自动补调生成。
- 若在收到原图前发生网络断开/超时，仍无法凭本地下载链接找回尚未收到的数据；本功能不新增异步任务系统，不保证跨刷新去重。状态不确定时先检查现有请求 ID 和服务日志。
- 飞书宿主可能对浏览器下载或 Canvas 有额外限制，仍需实际宿主验证；普通 Chromium 浏览器的原图下载已用 Mock 验证。

所有 OpenAI / 飞书调用使用 Mock。真实 Canvas 测试验证2880→4×1392、1600→4×752、象限独立内缩坐标、内外16px边线去除、透明/半透明RGBA、对应区域逐像素一致及顺序、四个独立附件、旧附件保留、复选框持久化、数量锁定/恢复、正常多图流程、非正方形/Canvas/上传失败不重扣费和原图实际下载。

本次24px内缩调整的运行时代码只改 `image-api.js`，不勾选时的图片输出、原图下载、内联SDK、模板、参考图、鉴权与Render服务文件保持原样。合并后手动更新 Pages 的 `image-api.js` 即可使用（其余已有静态文件继续保留）；**无需因本功能更新或部署 Render**，不会引入真实 Key。清理浏览器网站数据或换设备会重置本地复选框等设置。
