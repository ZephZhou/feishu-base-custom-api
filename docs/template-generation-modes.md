# 模板控制生成策略：主图2×2、详情3×1、标准图片

日常只需要选模板、检查 Prompt 和输出附件字段。生成策略由模板的 `generationMode` 字段决定，**不解析 Prompt 中的“3张”“4张”等文字**。原数量选择和独立裁切复选框的DOM节点保留：数量放入高级设置，旧复选框隐藏并作为兼容别名，不再日常手动操作。

## 新的两套默认模板

| 模板 | generationMode | API次数/返回图片 | 请求尺寸 | 本地输出 |
| --- | --- | --- | --- | --- |
| 主图模板 | `crop_2x2` | 一次、`n=1` | 2880×2880 | 左上、右上、左下、右下4张方图；保留现有24px内缩，输出1392×1392 |
| 详情页模板 | `crop_3x1` | 一次、`n=1` | 3456×2048 | 左、中、右3张9:16竖图；默认输出1116×1984 |
| 自建标准模板 | `standard` | 一次、`n=1～10` | 沿用合法尺寸 | 上传全部有效返回图片，不裁切 |

页面只读说明分别显示「1次API生成 → 自动裁切4张方图」「1次API生成 → 自动裁切3张9:16竖图」「标准图片生成，可选择1～10张」。拼版模式即使旧数据中的 n 大于1，也会在执行时强制 `n=1`；不会拆成3次或4次生成请求。

新的默认Prompt明确描述无边框、无间隔的等分拼版。已保存的用户Prompt不会自动改写：升级旧模板时，请自行确认它描述了正确的2×2或3×1布局、商品完整且不跨格，裁切无法重排画面或修复模型构图。

## 使用与保存

1. 选择图片模式，仍使用原 Render API 地址和独立 PROXY_TOKEN，选商品白底图及输出附件字段。4个已保存的品牌参考图继续自动放在商品行图片之后。
2. 选择模板，Prompt、策略、尺寸、标准模式数量和详情内缩选项会一起恢复。
3. 如需修改策略，展开「高级设置」选择主图2×2、详情3×1或标准模式。标准模式才显示可操作的1～10数量；拼版锁定1。自定义尺寸仍在高级设置。
4. 修改后点「保存模板」；「新建模板」保存新条目，重命名和删除功能保留。保存字段包括名称、Prompt、**输出附件列 ID 与所属数据表 ID**、generationMode、size、n，以及可选的详情内缩比例 `detailInsetRatio`。
5. 图片模式现在按「选择模板 → 商品输入与 Prompt → 输出到飞书」排列，品牌参考图和高级尺寸/数量设置折叠显示。主图和详情页可以分别绑定不同附件列，保存模板后切换自动恢复。
6. 旧模板不包含输出映射，需要首次选择目标附件列后点击「保存模板」一次。原有 Prompt、尺寸、图片与策略保持不变。切换数据表或字段被删除时，旧绑定自动标记为不可用、输出选择清空并提示重新选择，避免写错列。
5. 先单行、并发1验证，再批量执行。每批固定策略、数量、尺寸、Prompt和品牌图；中途切换模板只影响下一批。

成功日志按实际处理数量显示：主图「API生成1张，裁切4张，上传4张」、详情「API生成1张，裁切3张，上传3张」、标准「API生成n张，上传n张」，并保留行号、请求ID、阶段耗时和成功/失败汇总。

## 详情3×1像素裁切

`crop3x1()` 解码**实际返回图**，检查宽度可被3整除，并要求 `(宽度÷3)×16 = 高度×9`。不满足就明确报错，不用拉伸伪装比例。

- 3456×2048：每列1152×2048（9:16）。
- 默认安全内缩：每边约边长的1/64，左右18px、上下32px，得到1116×1984，仍精确9:16。
- 选择高级设置的「不内缩」：比例设为0，得到完整的1152×2048。选择后可保存进模板。
- 其他实际尺寸：将原始9:16列表示为 `9k × 16k`，内缩单位为 `round(k × detailInsetRatio)`，横向按9像素单位、纵向按16像素单位取整，确保比例精确。若内缩后没有有效像素则报错，不缩放或静默拉伸。

顺序为左、中、右，文件名前缀为「详情页01」「详情页02」「详情页03」。同一次 `batchUploadFile` 上传全部文件，取得全部token后以现有 `setCellValue` 方式追加，保留旧附件；默认仍跳过已填输出行。原来的 `crop2x2()` 坐标、顺序、24px内缩与像素处理保持不变。

## 旧模板与本地数据

- 新默认模板只用于没有保存模板数据的新浏览器。**已有主图/详情模板不会因同名而被替换**，也不会按名字/Prompt推断策略。
- 旧 `autoCrop2x2=true` → `crop_2x2`；false或缺少旧字段 → `standard`。新数据以明确的 `generationMode` 为准，即使旧别名不一致也不覆盖新策略。
- 迁移在内存中进行，不在读取时重写localStorage。显式保存/重命名时为混合的新旧条目补上新字段，保留名称、Prompt、尺寸及其他已有字段。
- 旧模板如果仍是标准模式，想改为3×1：选择它，在高级设置选详情3×1，宽3456、高2048，检查Prompt布局，然后保存。旧的方形裁切详情模板仍按 `crop_2x2` 保留，不会擅自更改用户尺寸。
- 旧草稿布局不合适时仍可加载、重命名，不会阻止保存另一个模板；但当前模板保存/执行时会做完整布局校验，非法尺寸在付费请求前拦截。
- 品牌图的IndexedDB数据库、版本和4个槽位不变，不清空、不迁移品牌图片。模板和配置继续使用原localStorage键，不增加数据库、服务器或框架。清理浏览器数据或换设备仍可能丢失本地配置。

## 失败恢复及后端兼容

原始拼版图先保留下载链接，再尝试裁切。返回尺寸不符、Canvas失败、上传或写回失败均不会重新调用收费API，也不会先清空旧附件。请在刷新或关闭前下载原图，链接只在当前页面内存中有效。附件追加仍是读当前值后一次写回，不提供跨客户端同时修改同一格的原子追加保证。

`3456x2048` 的宽高均为16倍数、长边小于3840、总像素7077888，`n=1`的结果估计37814272字节，符合现有64MiB预算。**不需要修改 `server/image-proxy.cjs` 或Render API行为**；mode与内缩字段只在前端使用，不作为新参数发送给OpenAI。现有超时、原图大小限制、内存准入、PROXY_TOKEN鉴权与CORS保持。大图建议并发1，Render实际可用内存、账户权限及生成时长仍需真实环境验证。

Pages需同步更新 `index.html`、`image-options.js`、`image-api.js` 和公开共享的 `server/image-rules.js`，保留其他文件。后端原有尺寸/数量校验已经支持3456×2048，不需要为此改动或自动部署后端。
