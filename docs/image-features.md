# 品牌参考图、多张生成、Prompt 模板和自定义尺寸

> 操作界面已升级为模板生成策略；本文的裁切/持久化原理仍适用，当前默认值与操作以 [模板策略说明](template-generation-modes.md) 为准。

本次沿用现有 Pages 插件和 Render 图片中转，不新增数据表或后端服务。API 地址、PROXY_TOKEN、Origin 校验、请求追踪和超时设置不变；中转仅增加数量/尺寸校验、多图片返回及结果容量保护。

## 使用步骤

1. 在飞书选择「图片生成」，保留原 API 地址及 PROXY_TOKEN，输入列选择当前商品的「白底图」，输出列选择附件字段（例如「主图」）。
2. 在「固定品牌参考图」的 4 个位置上传 PNG/JPEG/WebP。可以只用其中几个；重新上传即可替换，点「删除」移除，缩略图供预览。保存成功后重新打开仍可使用。
3. 选择「主图模板」：默认 4 张、1024×1024；选择「详情页模板」：默认 3 张、1024×1536。切换会覆盖编辑区的 Prompt、数量和尺寸；未保存的改动不会自动更新模板。
4. 编辑 Prompt、数量、尺寸，点「保存模板」更新当前模板；要新增模板，先选择「新建模板」并填写新名称，再保存。重命名仅改变名称；删除仅移除模板，不清空当前 Prompt。默认两个模板也能编辑和删除。
5. 「生成数量」支持 1～10。每个商品行只发 **一次** 图片请求，`n` 就是所选数量，不会拆成多次生图请求。数量会增加费用；批量成本还需乘以行数。先用一行、并发 1 验证。
6. 生成成功后将返回的全部有效图片一次上传飞书，追加到已选输出附件字段。默认仍跳过非空输出行；若要继续生成，选择「继续生成（保留旧附件并追加）」。图片模式不再清空旧附件；文本和视频的原有行为保持。

## 图片顺序与本地持久化

- 选中的「白底图」字段优先，当前行其他选中附件图随后，品牌图按槽位 1～4 最后追加。四张品牌图不会替代商品白底图，也不会加入文本/视频请求。
- 当前行图与品牌图合计最多 16 张；上传总量仍受中转 52MiB 限制，前端预留 multipart 空间，在文件合计超过 51MiB 时直接拒绝，不提交付费请求。单图必须小于 50MiB。
- 品牌图通过 **IndexedDB** 以文件 Blob 保存；模板在 **localStorage** 保存，不保存到 GitHub，也不自动同步到其他表或设备。同一浏览器同一网站 Origin 的插件共享这些本地设置。
- 清理网站数据、隐私模式退出、浏览器自动清理/存储回收、换设备、换浏览器或换 Pages 域名可能丢失设置；请保留原图与 Prompt 的自行备份。浏览器存储受限时会报错并停止品牌图生成，避免悄悄遗漏参考图；更换文件保存失败时旧图保留。
- 每批开始时固定数量、尺寸和已加载品牌图；在本批运行中更换这些设置只影响后续批次。

## 自定义尺寸

可继续选三种原有预设，也可直接填写宽、高。手动输入会切换为「自定义尺寸」，请求使用规范的 `WIDTHxHEIGHT` 字符串。

前后端共同校验 GPT Image 2 限制：宽高为正整数且都是 16 的倍数、宽高比在 1:3～3:1（含边界）、最长边 ≤3840、总像素在 655360～8294400（含边界）。合法示例：1536×864、1024×1024、1024×1536、3840×2160；1025×1024、512×512、1024×256 均不合法。尺寸不合法时页面显示中文原因，点击生成也不会发起图片请求。

超过 2560×1440 的分辨率属于官方标注的实验范围，实际可用性还受账户和模型能力约束。接口格式与倍数/比例核对来源为 [OpenAI 官方 SDK](https://github.com/openai/openai-node/blob/master/src/resources/images.ts)，完整规则以 [官方图像生成指南](https://developers.openai.com/api/docs/guides/image-generation) 为准；本环境访问指南站受限，未用真实 API 测试边界分辨率。

## 多张结果、内存和失败处理

- Render 仍只代理官方两个图片接口；仍固定 GPT Image 2、PNG 输出、全局最多两个活动请求。Node.js 22+、Root Directory `server`、Build `node --check image-proxy.cjs`、Start `npm start`、`/health` 及现有环境变量不变。
- 上游响应仍限制 **64MiB**。前后端会先按数量和尺寸估算未压缩 RGBA PNG 的 Base64 大小，超预算直接拒绝，不调用 OpenAI。例如 1024×1024 的 n=10 在容量预算内，3840×2160 的 n=2 则超出预算。界面提供所有 1～10 选项，但高分辨率与大数量不能任意组合。
- 中转还会根据进程可用内存、正在执行请求的预留量、上传大小和结果估计做调用前准入；内存不足时返回 503 和「本次未提交上游」提示。该估计是保守保护，不是内存耗用的精确保证。多图建议 **并发 1**；较多/较大的图片建议 Render 至少 **1GiB 内存**，避免与其他进程共用紧张内存。若平台直接 OOM 杀进程，应用无法返回自定义错误，仍需查看 Render 事件。
- 实际响应超 64MiB 时会截断接收，并返回「结果超限，可能已计费」的明确提示，不自动重试。UI、日志和错误均不记录图片/Base64、官方 Key 或令牌。
- 上游只返回部分图片时会保留有效图片并警告返回数与请求数不一致，不额外补调 API。所有返回图片校验后一次上传，只有全部附件 token 返回成功才更新单元格；上传失败不覆盖旧附件，也不重生图。已上传但回写失败的文件可能残留。
- 附件追加采用写入前读取当前值再一次写回，没有飞书跨客户端原子追加保证；避免多个插件同时操作同一输出单元格。当前同步生图仍不能跨页面刷新恢复未保存结果或保证手动重复提交不扣费，状态不明确时先核对原请求 ID，勿盲目重跑。

## 密钥

官方 OpenAI Key **仅**放在 Render 的 `OPENAI_API_KEY` 中。插件图片模式拒绝 `sk-` 开头的官方 Key，并清理旧配置中已保存的此类 Key；不会把它们重新写入 localStorage。前端填写独立 `PROXY_TOKEN`，它仍沿用原来的本地配置保存机制，应视为敏感凭证，不要共享浏览器配置或导出给他人。

## 更新与免费测试

不要只更新 HTML。Pages 需包含 `index.html`、`image-api.js`、`image-options.js` 和 `server/image-rules.js`；后端需包含更新后的 `server/image-proxy.cjs` 及同目录 `image-rules.js`。新数量和尺寸必须在手动更新后端后使用，旧中转会拒绝 n>1 和自定义尺寸。无需自动部署，本修改不触发手动部署操作。

```sh
node tests/image-api.test.cjs
node tests/image-features.test.cjs
npm --prefix server test
node tests/browser-smoke.cjs
node tests/browser-image-features.cjs
```

浏览器测试需要 Playwright 和 Chromium，当前云环境已有。测试通过 Mock 验证参考图顺序、模板增删改与重启、IndexedDB 品牌图替换/删除/预览、尺寸/数量、全部图片追加、上传失败保留旧结果、请求追踪与鉴权回归；不会使用真实 API Key 或付费调用。真实飞书宿主多附件上传、真实模型 n/分辨率和所选 Render 套餐仍需手动联调。
